# Tâche 1.1 — Modèle distant (API) ou modèle local léger

Auteur : Illane SIDIBE, Membre 3 (IA et Big Data)

## Besoin
Le module doit transformer un objectif en un plan structuré (JSON conforme au schéma),
en français, avec un format fiable et un coût maîtrisé. Les données envoyées sont
limitées (voir 1.2).

## Critères
| Critère | Modèle distant (API) | Modèle local léger |
|---|---|---|
| Coût | Paiement à l'usage ; à budgéter | Aucun coût d'usage ; coût du matériel |
| Latence | Quelques secondes, dépend du réseau | Dépend de la machine (RAM, GPU) |
| Qualité en français | En général meilleure | À tester ; plus d'erreurs probables |
| Fiabilité du JSON | Bonne ; validation et nouvelle tentative prévues | Plus variable ; nouvelle tentative plus fréquente |
| Confidentialité | Les données quittent la machine | Les données restent en local |
| Connexion | Indispensable | Non nécessaire après installation |
| Mise en œuvre | Clé d'accès à fournir et à protéger | Machine suffisamment puissante à désigner |

## Protocole de test (à compléter avec les résultats réels)
Deux ou trois options sont testées sur trois objectifs : examen, recherche de stage, activité physique.
Pour chacune, on relève : JSON valide du premier coup (oui/non), nombre de tentatives,
temps de réponse, qualité des étapes (note de 1 à 5), langue.

## Recommandation
À rédiger après les tests. Points à trancher avec la cheffe d'équipe :
1. Existence d'un budget et d'une clé fournie par le projet.
2. Machine désignée pour héberger un modèle local, le cas échéant.
3. Besoin de fonctionner sans connexion.

Le code est conçu pour que le modèle soit interchangeable (`src/modeles.py`) : le choix
peut évoluer sans modifier le reste du module.
