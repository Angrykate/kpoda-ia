# Tâche 2.5 — Garde-fous

## Règles
- L'IA propose, l'utilisateur valide.
- L'IA ne dit jamais avoir modifié un planning, une règle ou une restriction.
- Une hypothèse n'est jamais présentée comme une certitude.

## Dans les prompts
`prompts/garde_fous.txt` : texte à ajouter aux prompts qui produisent du texte destiné à
l'utilisateur (explications, rapports).

## Dans le code
- Statut obligatoire dans les schémas : `statut_proposition` de la décomposition, et
  `en_attente_de_validation` pour les plannings et replanifications. Un autre statut est refusé.
- `src/garde_fous.py` contrôle tous les textes d'une sortie. Sont refusées :
  - les actions prétendues (« j'ai déplacé », « votre planning a été mis à jour », « c'est fait ») ;
  - les certitudes (« il est certain que », « garanti », « tu réussiras »).
- `decomposer()` applique ce contrôle : une sortie refusée est redemandée au modèle, avec la
  raison du refus.

## Tests
`tests/test_garde_fous.py` : 7 phrases interdites, 5 phrases normales qui ne doivent pas être
refusées, contrôle d'une sortie imbriquée, et refus suivi d'une réponse correcte.

## Limite
Le contrôle repose sur des expressions : une formulation inhabituelle peut passer. La liste
est à compléter avec les cas relevés pendant l'évaluation (tâche 4.1).
